# 飞书样品跟踪表

## 定位

样品跟踪表连接合作记录、实际寄送、17TRACK 物流状态和飞书提醒。人工维护样品与运单信息，自动任务只写派生物流和提醒状态。

## 字段合同

| 分组 | 字段 |
| --- | --- |
| 标识与关联 | 多行文本、样品记录ID、合作自动编号、合作记录ID、联系邮箱、KOL Name |
| 人工寄送 | 样品明细、样品成本、样品运费、收件信息、样品状态、物流商、物流单号、发货日期、签收日期、备注 |
| 物流派生 | 物流商编码、已同步运单键、物流状态、最新物流进度、最新物流时间、物流停滞起算时间、物流源同步时间、上次查询时间、物流查询错误 |
| 提醒派生 | 提醒类型、提醒状态、提醒事件键、提醒发送时间、提醒错误 |

样品成本和样品运费为不预设币种符号、保留两位小数的数字字段。联系邮箱与收件信息从合作红人表查找引用。自动任务不得覆盖样品明细、样品成本、样品运费、收件信息、物流商、物流单号、发货日期或备注。

## 物流刷新

- 只选择样品状态为已寄出或异常、且已有物流单号的记录。
- 使用 17TRACK 注册/查询接口，按服务限制分批请求。
- 归一化待揽收、运输中、派送中、已签收、退回、异常等状态。
- 默认 20 小时内的成功数据不重复查询；可用 `--force` 强制刷新。
- 运单号变化时清理旧运单的派生物流和提醒事件。
- dry-run 不调用 17TRACK、不注册运单、不写飞书。

## 提醒

- 签收后的下一个自然日生成跟进提醒。
- 物流有轨迹但连续 72 小时无新节点时生成停滞提醒。
- 同一天的事件合并为一张卡片。
- 事件键和发送租约保证幂等；进程在发送前中断时复用原消息键恢复，发送结果不确定时转为待人工确认，不盲目重发。

## 手动执行

```bash
# 物流刷新 dry-run，不调用 17TRACK、不写飞书
python main.py refresh-sample-logistics --dry-run

# 刷新物流；成功后再手动执行提醒命令
python main.py refresh-sample-logistics
python main.py dispatch-sample-reminders
```

## 隐私与日志

日志只保留定位问题所需的脱敏信息。不得输出 API Key、完整运单号、收件地址、飞书原始 payload 或完整外部响应。日志与统计默认保留在 `output/sample_logistics/`，并按保留期清理。

## 验收

- 重复执行不会重复注册同一运单或重复发送同一事件。
- 查询失败不会错误推进为已签收。
- 运单变更不会沿用旧提醒状态。
