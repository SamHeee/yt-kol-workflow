# 飞书合作红人表

## 定位

合作红人表承接“发现网红”之后的人工运营过程。一位网红可以有多次合作，因此合作记录不能直接并入网红详情表。

完整 `feishu-setup` 会创建本表、相关公式/查找引用，以及“首次进入合作自动建档”工作流。

## 字段合同

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| 多行文本 | 文本 | 飞书物理主字段，保持空白 |
| 合作记录ID | 公式 | 优先使用手动编号，否则使用自动编号 |
| 联系邮箱 | 文本 | 合作入口与查重键 |
| Channel Name | 查找引用 | 从网红详情表读取 |
| KOL Name | 查找引用 | 从网红详情表读取 |
| Channel ID | 查找引用 | 从网红详情表读取 |
| 合作项目、合作形式 | 文本 | 人工运营信息 |
| 收件信息 | 文本 | 样品寄送信息 |
| 合作状态 | 单选 | 待确认、执行、验收、完成等状态 |
| 合作负责人 | 人员 | 当前负责人 |
| 下一节点、下一节点日期 | 文本、日期 | 跟进安排 |
| 交付/发布链接 | URL | 交付结果 |
| 备注 | 文本 | 人工补充 |
| 自动编号 | 自动编号 | 系统生成的稳定编号 |
| 手动编号 | 文本 | 可选的历史编号兼容入口 |
| 邮箱索引 | 公式 | 规范化邮箱，默认视图隐藏 |

## 自动建档

当网红详情首次进入合作状态时，Workflow：

1. 检查 Channel ID 和联系邮箱等必要值；
2. 规范化邮箱；
3. 查询是否已有合作记录；
4. 仅在不存在时创建新记录；
5. 保留人工运营字段，不覆盖已有合作。

重复触发不得重复建档。没有邮箱的记录留在网红详情表中等待人工补充，不猜测收件人。

## 下游关系

- 样品跟踪表使用合作自动编号关联合作记录，并查找引用邮箱与收件信息。
- 合作内容数据表使用合作自动编号关联合作记录，并读取 Channel ID、KOL Name 和合作记录 ID。

## 验收

- 重复执行 setup 不重复创建表或字段。
- 同一邮箱重复进入合作不会产生重复合作记录。
- 第二次合作可由人工创建新的合作记录。
- 自动化不覆盖负责人、方案、备注、收件信息等人工字段。
- 任何类型冲突会停止并报告，不进行破坏性迁移。
